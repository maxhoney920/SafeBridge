# VlessBridge

Расширение для Chromium-браузеров (Chrome, Edge, Brave, Яндекс Браузер, Vivaldi, Chromium) и программа-помощник со встроенным [Xray-core](https://github.com/XTLS/Xray-core). Пользователь вставляет ссылку-подписку, выбирает сервер и сайты, которые нужно пускать через VPN.

```
[расширение] ── native messaging ──▶ [vlessbridge: помощник + встроенный Xray-core]
     │                                         │
chrome.proxy (PAC) ─▶ SOCKS5 127.0.0.1:порт ──▶ VLESS (XHTTP, Reality…) ─▶ сервер
```

## Возможности

| Что нужно было | Как сделано |
|---|---|
| Серверы из ссылки-подписки | base64-список ссылок, обычный список, JSON-конфиги Xray. Учитываются заголовки `subscription-userinfo` (трафик, срок), `profile-title`, `profile-update-interval` |
| Автообновление раз в 2 часа и вручную | `chrome.alarms` (интервал меняется в настройках, по умолчанию 120 мин). Кнопка «Обновить» в окне расширения. Если домен подписки заблокирован, повторная загрузка идёт через уже работающий VPN |
| Выбор сервера | Список в окне расширения, пинг всех серверов. Переключение без перезапуска ядра (балансировщик Xray + `xray api bo`, ~20 мс), выбор сохраняется при обновлении подписки (ID по параметрам подключения, а не по имени) |
| Только определённые сайты | Три режима: «Все сайты», «Только список» (через VPN только список «Через VPN») и «Исключения» (через VPN всё, кроме списка «Без VPN»). Домен включает поддомены, `ru` — всю зону .ru. Сайт добавляется из окна расширения одной кнопкой, есть готовые наборы: YouTube, Instagram, ChatGPT — для VPN; Госуслуги, банки, маркетплейсы, зона .ru — без VPN |
| Простая установка | Кнопка «Скачать для …» в окне расширения сама выбирает файл под систему и процессор и качает его с GitHub (ветка `downloads`). Права администратора не нужны: помощник копирует себя в профиль пользователя и регистрируется во всех найденных браузерах. Для macOS/Linux есть и команда `curl … \| sh` |
| Обновления | Раз в сутки расширение проверяет обновления. **Ядро Xray** обновляется автоматически из официальных релизов XTLS: SHA-256 сверяется с `.dgst`, текущие серверы проверяются новым ядром (`xray run -test`), а если новое ядро не запустится — возвращается прежнее. **Помощник** обновляется одной кнопкой: новая версия скачивается из ветки `downloads`, SHA-256 сверяется с `latest.json`, файл подменяется, браузер перезапускает помощник |
| Windows, macOS, Linux | Сборки amd64 и arm64 для всех трёх |

Протоколы: VLESS (XHTTP, Reality, TLS, Vision, WS, gRPC, HTTPUpgrade, mKCP, VLESS Encryption), Trojan, VMess, Shadowsocks (включая 2022), Hysteria2 (включая obfs salamander). Серверы, которые Xray запустить не может, видны в списке серыми с причиной:
- VLESS без TLS/Reality/Encryption на публичный адрес — Xray такое запрещает;
- транспорты HTTP/2 и QUIC — удалены из Xray (их заменил XHTTP);
- VMess с `alterId` больше 0, плагины Shadowsocks, диапазоны портов Hysteria2.

`allowInsecure=1` в ссылках игнорируется: в Xray эта опция удалена. Для сервера с самоподписанным сертификатом используйте параметр `pcs` (SHA-256 сертификата, `xray tls hash --cert cert.pem`), его понимают и v2rayN, и VlessBridge.

Дополнительно:
- защита от утечки IP через WebRTC в режиме «Все сайты»;
- при падении ядра прокси сразу снимается (страницы не «висят»), на иконке появляется «!», ядро перезапускается автоматически (до 3 раз за 2 минуты);
- при смене сервера Chrome сбрасывает старые соединения, поэтому уже открытые сайты тоже переходят на новый сервер;
- при закрытии браузера помощник и ядро завершаются. На Windows ядро в Job Object, на Linux — `PDEATHSIG`, на macOS остатки добиваются по pid-файлу.

## Структура

```
extension/          расширение MV3 (без сборки, чистый JS)
  src/background.js  связь с помощником, подписки, прокси, будильник
  src/popup.js       окно расширения
  src/options.js     настройки: подписки, списки сайтов, параметры, диагностика
host/               помощник на Go (только стандартная библиотека)
  links.go           разбор vless:// vmess:// trojan:// ss:// hy2:// → outbound Xray
  sub.go             загрузка и разбор подписки
  core.go            конфиг Xray, запуск, переключение (api bo), пинг через отдельные SOCKS-входы
  install*.go        установка и удаление, регистрация в браузерах
build.sh            сборка всех платформ со встроенным Xray-core
install.sh          установщик для macOS/Linux
.github/workflows/  релиз на GitHub по тегу v*
```

Xray-core встраивается в помощник как сжатый официальный бинарник (помощник целиком ~20 МБ). При первом запуске он распаковывается в каталог данных:
- Windows: `%LOCALAPPDATA%\VlessBridge`
- macOS: `~/Library/Application Support/VlessBridge`
- Linux: `~/.local/share/vlessbridge`

Так ядро обновляется заменой версии в `build.sh`, без правки кода, а помощник собирается на любом Go ≥ 1.22.

## Как выпустить

1. Поднимите версию в `extension/manifest.json` и запушьте в `main`.
2. GitHub Actions соберёт помощник под все платформы и перезапишет ветку `downloads` (один коммит, без истории бинарников). Оттуда файлы качают кнопка в расширении, `install.sh` и обновление помощника (`latest.json`).
3. По желанию — тег `v*`: тот же набор файлов прикрепится к релизу GitHub.
3. Расширение:
   - **для себя и знакомых:** распакуйте `vlessbridge-extension-*.zip`, откройте `chrome://extensions`, включите «Режим разработчика» и нажмите «Загрузить распакованное». ID будет `mpmmjdhamocialllnfmcpkjealmekhpl`, он зафиксирован ключом в `manifest.json`;
   - **для всех:** опубликуйте zip в Chrome Web Store, а полученный ID добавьте в переменную репозитория `EXTENSION_IDS` (через запятую со старым) и выпустите новую версию помощника. Без этого браузер не разрешит расширению запускать помощник.

Локальная сборка: `./build.sh` (или `./build.sh linux/amd64`), результат в `dist/`.

## Установка для пользователя

1. Установить расширение. При первом открытии оно само покажет, что нужен помощник, и даст кнопку для своей ОС.
2. Windows: запустить `vlessbridge-windows-amd64.exe`. SmartScreen предупредит о неизвестном издателе: «Подробнее», затем «Выполнить в любом случае».
   macOS/Linux: вставить в терминал команду из окна расширения.
3. «Проверить», затем вставить ссылку-подписку и включить.

Удаление помощника: `vlessbridge uninstall` (файл лежит в каталоге данных).

## Что стоит знать

- **Проксируется только браузер.** Остальные программы идут напрямую — так и задумано.
- **Подпись бинарников.** Без подписи Windows показывает SmartScreen, а антивирусы иногда ругаются на любые прокси-клиенты. Для массового распространения нужен code signing сертификат (Windows) и Apple Developer ID с нотаризацией (macOS). Установка через `curl | sh` на macOS обходит Gatekeeper законно, потому что файл не получает атрибут карантина. При двойном клике по скачанному файлу macOS его заблокирует.
- **Firefox** не поддержан: другой формат манифеста native messaging и `browser.proxy.onRequest` вместо PAC. Портировать можно, логика помощника та же.
- Если прокси в браузере уже настроен другим расширением, VlessBridge покажет предупреждение: Chrome отдаёт управление прокси только одному расширению.
- Отладка: в настройках, раздел «Помощник», есть журнал ядра. `vlessbridge parse файл` показывает, как разбирается подписка.

## Проверено

- `go test` (`host/links_test.go`): разбор ссылок всех типов, base64 и JSON-подписок, дедупликация, конфиг.
- Тестовые серверы Xray и sing-box: VLESS XHTTP+TLS, VLESS XHTTP+Reality, VLESS Reality Vision, VLESS WS, Trojan gRPC, Shadowsocks 2022, VMess HTTPUpgrade, Hysteria2 с salamander — через каждый страница загружается, пинг измеряется.
- Сквозной тест в Chromium 155 на этих серверах: добавление подписки, включение, загрузка страницы через VPN, пинг, переключение серверов, все три режима сайтов, ручное обновление подписки, интервал 2 часа, падение ядра и автоперезапуск, выключение, завершение процессов при закрытии браузера.
- Установщик и удаление на Linux. Сборки под Windows и macOS проходят `go vet`, но на этих системах вживую не запускались.
