# Безопасность SafeBridge

Первый аудит проведён 30 октября 2026 года для версии 0.5.0, повторный — для 0.6.1 (расширение для Chromium и Firefox, вход в аккаунт safe-internet, помощник, ядро Xray, установщик, сборка в CI).

## От чего защищаемся

| Кто | Что может | Чего не должен суметь |
|---|---|---|
| Сайты в браузере | загружать страницы и скрипты | управлять расширением или помощником, узнать настоящий IP, если сайт идёт через VPN |
| VPN-сервис (владелец подписки) | выбирать серверы и их параметры | читать или писать файлы на компьютере, запускать программы, направлять трафик мимо VPN |
| Сеть между вами и VPN-сервисом | видеть и менять незашифрованный трафик | подменить помощник или ядро |
| Другие программы и пользователи этого компьютера | работать от своего имени | перенаправлять ваш трафик мимо VPN |
| Тот, кто подменил файлы в ветке `downloads` или по дороге к ней | отдавать любые файлы | заставить помощник или `install.sh` поставить чужой помощник |
| Тот, кто взломал аккаунт GitHub | менять код и CI | — (см. «Что осталось») |

## Найдено и исправлено в 0.5.0

| | Проблема | Как было | Что сделано |
|---|---|---|---|
| **Высокая** | **Управляющий API ядра был открыт всем программам компьютера.** У Xray был включён API без пароля на `127.0.0.1`. Любая программа, в том числе от другого пользователя, могла добавить правило «всё напрямую» и незаметно пустить трафик мимо VPN. Проверено: подменить маршруты удалось одной командой `xray api adrules`. | API нужен был для переключения серверов без перезапуска | API убран. Сервер переключается перезапуском ядра (≈0,2 с). В конфиге ядра остались только SOCKS-входы на `127.0.0.1` |
| **Высокая** | **JSON-подписка могла писать в файлы на компьютере.** Параметры outbound из JSON-подписки передавались ядру как есть. Сервер подписки мог указать `tlsSettings.masterKeyLog: "<любой путь>"`, и ядро дописывало в этот файл ключи TLS-сессий. Проверено: файл появился. Так же можно было указать чтение сертификатов с диска, привязку к сетевому интерфейсу и цепочки через другие outbound. | — | Outbound из подписки очищается по белому списку. Ключи `masterKeyLog`, `certificates`, `certificateFile`, `keyFile`, `sockopt`, `dialerProxy`, `proxySettings`, `sendThrough` удаляются на любой глубине. Очистка выполняется дважды: при разборе подписки и перед запуском ядра, поэтому старые сохранённые данные тоже чистятся |
| **Средняя** | **Утечка настоящего IP при обрыве VPN.** Если ядро падало или помощник не запускался, расширение снимало прокси, и сайты молча открывались напрямую. | Сделано, чтобы страницы не «висели» | Kill switch, включён по умолчанию: пока VPN включён, но соединения нет, сайты, которые должны идти через VPN, не открываются, а окно расширения пишет «сайты заблокированы». Проверено в Chromium и Firefox: напрямую не уходят. Выключается в настройках («Если VPN пропал») |
| Средняя | **Ядро Xray при сборке не сверялось** с контрольными суммами. | Скачивалось с GitHub и встраивалось как есть | `build.sh` сверяет SHA-256 каждого архива Xray с официальным `.dgst` XTLS. При несовпадении сборка останавливается |
| Средняя | **Действия GitHub Actions подключались по тегам** (`@v4`). Тег можно перевесить на другой код. | — | `checkout`, `setup-go` и `action-gh-release` закреплены по SHA коммита |
| Низкая | **Подписка по `http://`** может быть подменена по дороге: чужие серверы, перехват трафика. | Принималась молча | В настройках у такой подписки предупреждение |
| Низкая | **Ссылка подписки (личный токен) попадала в `host.log`** при ошибках загрузки. | — | Ссылки в журнале заменяются на `<ссылка>` |

## Найдено и исправлено в 0.6.1

| | Проблема | Что сделано |
|---|---|---|
| **Высокая** | **Обновления помощника не были подписаны.** Помощник сверял SHA-256 нового файла с `latest.json`, но оба лежали в одной ветке `downloads`: подменив оба, можно было выдать свой помощник всем, кто нажмёт «Обновить» или поставит через `install.sh`. | CI подписывает `latest.json` ключом ed25519 (секрет `UPDATE_SIGNING_KEY`, файл `latest.json.sig`). Открытый ключ встроен в помощник: без верной подписи он не показывает обновление и не ставит его. Имена файлов из `latest.json` проверяются (только буквы, цифры, `.`, `-`, `_`). `install.sh` тоже проверяет подпись там, где есть OpenSSL 3 (Linux), и всегда — SHA-256 скачанного файла |
| Средняя | **Токен входа мог остаться в истории браузера.** После входа сайт передаёт токен в адресе страницы `/ext/done#token=…`, а скрипт расширения запускался после загрузки страницы. | Скрипт расширения запускается в самом начале загрузки (`document_start`) и сразу стирает токен из адреса. Если расширения нет, его стирает сама страница. Страница и ответы API отдаются с `Cache-Control: no-store`, `Referrer-Policy: no-referrer` и запретом показа во фрейме |
| Средняя | **Фон расширения принимал любые команды от скрипта на сайте аккаунта.** Скрипт отправляет только итог входа, но фон не проверял, откуда пришло сообщение. Если бы этот скрипт удалось обмануть, он мог бы, например, включать прокси или менять списки сайтов. | Страницы расширения могут всё, скрипт на сайте — только сообщить итог входа. Сообщения от других расширений отклоняются |
| Низкая | **Токен аккаунта отдавался окнам расширения** вместе с остальным состоянием. | Токен остаётся только в фоне |
| Низкая | **Адрес сайта аккаунта можно было переопределить** в хранилище расширения (нужно для проверки): подменивший хранилище отправил бы токен на чужой сайт. | Переопределение работает только для `127.0.0.1` и `localhost` |
| Низкая | **`updateSub` принимал любые поля подписки**, например адрес или признак «из аккаунта». | Можно менять только имя |
| Низкая | **Сайт копил одноразовые `state` входа**: `/ext/login` может открыть кто угодно сколько угодно раз. | Просроченные записи удаляются при каждом новом входе |
| Низкая | **Список «Ещё N сайтов мимо VPN» не был ограничен**: страница может нарочно загрузить что угодно. | Не больше 30 доменов, и добавляются они только по кнопке |
| Справка | **Папка `keys/` в репозитории.** В ней были только открытый ключ расширения и его ID — они и так есть в `manifest.json`. Закрытый ключ (`dev-extension-key.pem`) в git никогда не попадал: он был в `.gitignore`. | Папка удалена из репозитория, `keys/` и `*.pem` в `.gitignore`. Закрытый ключ нужен только чтобы собрать `.crx` с тем же ID; храните его у себя |

## Проверено и в порядке

- **Расширение.** Нигде не используются `innerHTML`, `eval` и подобное. Все данные с серверов (имена, ошибки) выводятся как текст. Сообщения принимаются только от своих страниц (`onMessage`, без `externally_connectable` и `web_accessible_resources`). Единственный content script работает на странице `/ext/done` сайта аккаунта и может только передать итог входа; другие сайты обратиться к расширению не могут.
- **PAC-скрипт** (Chrome). Домены проходят нормализацию до `[a-z0-9.-]` и вставляются через `JSON.stringify`, внедрить код через список сайтов нельзя.
- **Помощник.** Браузер запускает его только для расширения с указанным ID (`allowed_origins` / `allowed_extensions`). Размер сообщений ограничен (64 МБ на вход, 1 МБ на ответ), подписка ограничена 8 МБ. Конфиг с ключами серверов (`config.json`) имеет права 0600, папка данных 0700. При закрытии браузера ядро завершается.
- **Ссылки подписки.** `allowInsecure` игнорируется: в Xray эта опция удалена, отключить проверку сертификата из ссылки нельзя. Проверка своего сертификата возможна только через отпечаток `pcs`. VLESS без шифрования на публичный адрес не запускается.
- **Обновление ядра** берётся только из официальных релизов `XTLS/Xray-core`, сверяется SHA-256 из `.dgst`. Перед переключением новое ядро проверяет текущий конфиг (`xray run -test`), при ошибке остаётся старое. Понижения версии нет.
- **Вход в аккаунт.** Вход начинает само расширение с одноразовым `nonce` (24 случайных байта, живёт 15 минут); токен принимается только вместе с ним и только со страницы `/ext/done` сайта аккаунта, поэтому подсунуть чужой токен по ссылке нельзя. Токен — 32 случайных байта, на сайте хранится только его SHA-256, открывает только список ключей и выход, живёт 90 дней без использования, на пользователя не больше 10 токенов. «Выйти» отзывает токен на сайте. Новых пользователей вход не создаёт.
- **Проверка новой версии расширения** (Chrome) только читает версию из `latest.json` и показывает ссылку на архив в ветке `downloads`; имя файла проверяется, сама ничего не скачивает и не устанавливает.
- **DNS.** Сайты, идущие через VPN, разрешаются на стороне сервера (Chrome — SOCKS5, Firefox — `proxyDNS`). Нет телеметрии, аналитики и сторонних запросов, кроме подписки, GitHub (обновления) и адреса для пинга.

## Что осталось и требует решения

1. **Аккаунт GitHub и CI.** Подпись обновлений защищает от подмены файлов, но ключ подписи хранится в секретах репозитория: тот, кто получит доступ к аккаунту или сможет менять CI, подпишет что угодно. Включите двухфакторную аутентификацию в GitHub и защиту ветки `main`. Помощники 0.6.0 и старше подпись ещё не проверяют — защита начинает действовать после обновления до 0.6.1. Ручная загрузка файла по ссылке и `install.sh` на macOS проверяют только SHA-256.
2. **Подпись бинарников и дополнения.** Файлы не подписаны: Windows показывает SmartScreen, macOS — Gatekeeper, расширение для Chrome ставится в режиме разработчика. Нужны сертификат подписи кода (Windows) и Apple Developer ID с нотаризацией (macOS). Дополнение для Firefox уже подписывается Mozilla в CI.
3. **ID расширения.** В режиме разработчика ID получается из открытого ключа в `manifest.json`, а в Firefox его задаёт строка `vlessbridge@safebridge`. Расширение, загруженное вручную с тем же ключом или ID, сможет управлять помощником. Это требует, чтобы его установили в ваш браузер в режиме разработчика. После публикации в Chrome Web Store и AMO стоит разрешать помощнику только ID из магазинов.
4. **Локальные SOCKS-порты без пароля.** Основной вход ядра и входы для пинга слушают `127.0.0.1` без авторизации: Chrome не умеет SOCKS с паролем. Другая программа или другой пользователь этого компьютера может пользоваться вашим VPN-подключением. Ваш трафик он не увидит и маршруты не изменит.
5. **Защита WebRTC** работает только в режиме «Все сайты». В режимах «Только список» и «Исключения» сайт может узнать настоящий IP через WebRTC — это ограничение браузера, а не ошибка.
6. **Папка помощника доступна на запись** вашему пользователю. Вредоносная программа, уже работающая от вашего имени, может подменить помощник. От этого защищает только подпись бинарников (пункт 2) и антивирус.

Откройте [приватное сообщение об уязвимости](https://github.com/maxhoney920/SafeBridge/security/advisories/new) на GitHub, а не публичный issue.
